# Browser Mods interaction design

Status: unified workspace navigation implemented, 2026-11-27. One extension with Redact 0.3.1, shared GitHub Dark Default tokens, and locally styled shadcn Input and Radix Dropdown Menu adaptations. New feature implementations remain in the feature roadmap.

## Everyday interaction

Direct Chrome commands execute existing actions without rendering UI. The unassigned `open-palette` action opens search independently of the toolbar home. Configure its key through Chrome’s shortcut editor. The four suggested defaults still apply.

Chrome displays command descriptions in its shortcut editor but sorts and stores bindings by manifest command ID. The build prefixes native IDs with the catalog category so related commands appear together. Chrome treats the move to these prefixed IDs as new commands, so existing assignments may need to be set again. Internal IDs continue to identify actions in preferences, history and backups. Keep published native IDs stable, including their category prefixes. Editing descriptions or adding commands preserves existing bindings.

The toolbar action opens the same Favorites start view on every tab. The popup requests 800 × 600 pixels and fits narrower viewports with a horizontally scrolling category rail. All actions groups commands by workflow, and the rail opens each workflow directly. Open a row menu to pin an action or go to its feature settings. Search covers commands from every category, and Escape returns to the category you were browsing. Playlist duration lives under Media. RDP setup is under Web tools in Options and can be opened with the source tab from Web tools in the popup.

Pins, visibility, action ordering, search mode and palette placement use the existing versioned preference keys. Legacy popup layout and section-order fields still round-trip through sync and backups. They no longer change the shared navigation. Concurrent changes to separate controls merge independently. Chrome resolves concurrent writes to the same key. Saving locally does not prove remote delivery.

Palette placement is toolbar (default) or an on-demand centered launcher. The latter uses a modal native dialog and isolated extension iframe, with a short-lived session authorization bound to the source tab, a private MessageChannel, explicit readiness handshake, and focus restoration. Unauthorized embedded launchers do not render; privileged requests revalidate the session and active tab. Unsupported pages or denied injection use the toolbar fallback. No launcher listeners, polling, or page scripts run before invocation.

Search modes are actions/scoped searches (default), everything grouped by result type, or commands only. Disabled actions may appear in search if explicitly enabled in Appearance & controls. Roadmap items stay in project documentation. Search matches descriptions, command IDs, categories and aliases. Tab metadata is fetched when entering its search mode, not for every character; bookmark search is optional-permission, debounced, and stale results are discarded. Search renders at most 100 results; refine the query for others. Extension/profile search becomes available with the actual extension manager, rather than returning fictional entries.

Arrow keys navigate results, Enter runs, and Escape clears a query, returns from scoped search, then dismisses. One-shot actions close; toggles stay open. Errors are actionable; routine success notifications are omitted. Future persisted jobs must expose progress/cancellation without depending on popup lifetime; no new long-running job module is implemented here.

## Options and maintenance

Options has a persistent sidebar with Features, Shortcuts, Appearance & controls, Site access, and Sync & backup. Features are grouped by the same workflows as the popup. The URL records the feature page and targeted control, including support for old bookmarks, Back and Forward. Search and palette settings results navigate to the matching control. Available mod switches gate commands in every surface, including native maintenance tools. Tabs’ existing bounded recent-history service remains shared infrastructure when tab commands are disabled; Media and Clipboard have no feature observers while disabled.

Shortcuts shows the browser’s actual bindings and links to Chrome’s shortcut editor. The secondary assignment history view shows actual and desired bindings and observed device revisions. Explicit adoption can include an empty binding and creates a causally newer revision. Keeping the desired assignment requires no write; Chrome still owns actual assignment. The existing shortcut backup and tab-switch behavior screens remain available as native maintenance views; the options page embeds the existing history view rather than rewriting it twice.

Interface backups use a versioned, strictly validated JSON envelope, a 64 KiB input limit, one sync write, and a local pre-import recovery snapshot. Import does not assign browser keys or grant permissions. Shortcut backups retain their existing separate format and safeguards. Optional site grants can be revoked from options.

## Engineering and verification

Workspace feature adapters own browser access, pure preference policy owns normalization/validation, and feature UI owns search and presentation. Options UI is a separate entrypoint dependency and is absent from popup/launcher bundles. Privileged actions use existing typed worker dispatch; the renderer stays out of worker/offscreen output. TSX participates in strict typing, typed lint, dependency/context checks, Knip and negative fixtures. React-facing imports resolve to pinned Redact; production metadata rejects actual React/ReactDOM and test instrumentation.

The menu uses the pinned Radix dropdown package and its positioning implementation. The input and menu source are adapted from shadcn’s MIT-licensed New York registry with the existing CSS pipeline. The desktop helper and site permissions are unchanged by this UI layer. The in-page preview fixture covers a selection control, bookmark folder picker and duplicate review using sample data. It is served only by the test harness and is excluded from the extension package. Zod remains the documented candidate for broader shared schemas; this small fixed preference boundary follows existing explicit validators. Revisit indexing/virtualization with real large tab/bookmark workloads, rather than scanning every feature or installing a generic automation framework.

Packaged tests cover category navigation, menu keyboard focus restoration, pinning, narrow viewports, live synchronization, search modes, settings links, browser history, malformed imports and unauthorized launchers. A separate centered-launcher fixture adds localhost host access only in its disposable manifest so injection can be tested without changing production grants; it checks the handshake, Escape, focus restoration and repeat-invocation cleanup. Existing native maintenance, media, clipboard, and tab operation suites remain regression coverage.
